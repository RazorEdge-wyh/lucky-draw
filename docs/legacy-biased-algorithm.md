# 原始算法备份：加权抽样 + 整轮必中

> 这份文档是项目**最初那套有偏算法的完整记录**。
> 当前默认已经是均匀随机；这个文件是为了将来还能把老算法原样找回来。

---

## 它是什么

一段「伪装成随机、但结果被规则锁定」的抽奖算法。规则：

| 项目 | 值 |
| --- | --- |
| 号码池 | 1 – 8 |
| 一轮 | 9 次 |
| 特殊号码 | 4 |
| 特殊号码单次权重 | 15% |
| 其余 7 个号码 | 各约 12.14% |
| **保证** | 一轮九次抽完，**4 一定出现过，且票数严格多于其他任何号码** |

也就是说：**4 是否「中奖」由规则决定，不是随机决定的；随机只决定其余号码怎么分布。**

实测结果分布（5000 轮）：4 占 **37.15%**，其他号码各约 **9.0%**。
注意这个比例**不等于单次权重**（15% / 12.14%），因为「整轮必中」把 4 的占比条件化抬高了。

## 算法两步

```
        ┌──────────────────────────────────────┐
        │ 第一步：加权抽样（每轮 9 次）          │
        │ 4 号 15% ┊ 其余 7 个号码各 12.14%      │
        └──────────────────┬───────────────────┘
                           ▼
        ┌──────────────────────────────────────┐
        │ 第二步：整轮校验                       │
        │ 4 的出现次数 > 其他每一个号码？         │
        └──────┬──────────────────┬────────────┘
            是 │                  │ 否
               ▼                  ▼
          返回结果          整轮作废，重抽
                          （最多 5000 次，
                            超限则构造式兜底）
```

关键点：重抽是**整轮重来**，不是只换掉冲突的几个号码。

## 单轮自然命中率（解析解）

一轮结果服从多项式分布。设 4 出现 $k$ 次，「4 唯一最多」等价于其他每个号码出现次数 $\le k-1$：

$$
P(\text{命中}) = \sum_{k=1}^{9} \binom{9}{k} \cdot M(9-k,\ 7,\ k-1) \cdot 0.15^{k} \cdot 0.1214^{\,9-k}
$$

其中 $M(r, m, L) = \sum \dfrac{r!}{\prod_i c_i!}$ 是对所有满足 $\sum_i c_i = r$、$0 \le c_i \le L$
的计数向量求和（**多项式系数之和**，不是解的个数 —— 漏掉这个因子会把概率算小约 143 倍，
这是一个真实踩过的坑）。

用整数动态规划精确计算：

```
dp[0] = 1
for 每个盒子:
    for j in 0..r:
        for c in 0..L:
            dp[j+c] += dp[j] * C(r-j, c)
```

结果：**单轮命中率 0.1113053438**，期望重抽 **8.98 轮**。逐项：

| $k$ | 多项式系数之和 | 该 $k$ 的贡献 | 实测占比（80 万轮） |
| --- | --- | --- | --- |
| 2 | 5 040 | 0.0015891 | 0.001656 |
| 3 | 83 790 | 0.0761501 | 0.075795 |
| 4 | 16 590 | 0.0279374 | 0.027809 |
| 5 | 2 401 | 0.0049946 | 0.005071 |
| 6 | 343 | 0.0005876 | 0.000586 |
| **合计** | | **0.1113053** | **0.110963** |

## 兜底构造

重抽超过 `MAX_ATTEMPTS`（默认 5000）时不再重抽，直接构造一个满足约束的序列：

1. 找最小的 $k$，使「4 出现 $k$ 次、其他号码各最多 $k-1$ 次」能填满 9 个位置，
   即 $9-k \le 7(k-1)$。默认参数下 $k=2$。
2. 填入 $k$ 个 4，剩下的位置轮流分配给其他号码。
3. 洗牌打乱顺序。

## 怎么把老算法找回来

代码里它**没有消失**，只是不再是默认值：

```bash
# 方式一：环境变量启用（服务端）
SPECIAL_NUMBER=4 SPECIAL_PROB=0.15 go run .
```

```go
// 方式二：直接调用备份实现（internal/engine/biased_backup.go）
cfg := config.Default()
cfg.SpecialNumber = 4   // 非 0 即启用有偏模式
cfg.SpecialProb = 0.15

g, err := engine.NewBiasedGenerator(cfg)
seq := g.DrawSequence()  // 一轮 9 个号码，保证 4 是唯一最高票
```

```go
// 方式三：走 Engine 的老路径（结果与方式二一致）
e, _ := engine.New(cfg)          // cfg.SpecialNumber = 4
seq := e.DrawSequenceBiased()    // 显式调用有偏路径
```

```javascript
// 方式四：静态版（site/index.html）—— 老逻辑已从页面移除。
// 需要恢复的话，参考本文档的算法描述重写 buildPool/pick/generateRound 三个函数。
```
